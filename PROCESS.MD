Currently We have a few things that are enabling a smooth and trackable process for building features

# Commits
Commits follow the conventional commits guidelines - and it implemented already in my git commit using an editor
These will enable descriptive messages following this format:
    type(scope):

# Pull Requests
Every change must go through a pull request on the dev, main and stable branches.
These branches are restricted by default so you cannot push without making a pull request
We will follow a feature branch model. Every pull request must reference an issue:



#Feature Branches must follow the following naming convention
- feat/123-page-allocator
- fix/77-grub-timeout
- chore/210-ci-cleanup
- docs/54-memory-map-notes
- refactor/88-pmm-structure
